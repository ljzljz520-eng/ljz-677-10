# 财政补贴名单导入平台

乡镇经办人上传补贴名单（补贴对象、身份证号、银行卡号、金额、乡镇），系统自动完成
**格式校验 + 重复校验**，校验通过的记录**分批上送财政平台**，平台退回的异常记录生成
**错误清单**（可导出、可重试）。不同乡镇账号数据隔离，只能查看本乡镇的导入任务。

## 功能特性

| 模块 | 说明 |
| --- | --- |
| 账号体系 | 乡镇经办人 / 县级管理员两级角色，密码哈希存储 |
| 数据隔离 | 乡镇账号只能查看、操作本乡镇的导入任务（越权访问返回 403） |
| 文件导入 | 支持 `.csv`（UTF-8/GBK 自适应）和 `.xlsx`，表头列名自动识别（支持别名） |
| 格式校验 | 身份证（18位+出生日期+校验位）、银行卡（16-19位+Luhn）、金额（>0、两位小数、上限）、姓名（2-30汉字）、乡镇归属 |
| 重复校验 | 文件内重复 + 库内重复（与历史"待上送/已发放"记录比对，防止重复发放） |
| 分批上送 | 校验通过记录按每 50 笔一批上送财政平台，逐批记录受理结果 |
| 错误清单 | 格式校验失败 + 平台退回记录汇总，支持导出 CSV（带 BOM，Excel 直接打开） |
| 失败重试 | 平台退回记录可一键重新上送 |

## 快速开始

```bash
pip install -r requirements.txt   # Flask + openpyxl
python db.py                      # 初始化数据库并创建演示账号
python scripts/generate_sample.py # 生成演示用导入文件（可选）
python app.py                     # 启动服务 http://127.0.0.1:5000
```

## 使用流程

1. **登录**乡镇账号 →「新建导入」上传名单文件（可先下载模板）；
2. 系统逐行校验，任务详情页查看**校验通过/失败**明细及失败原因；
3. 点击**「上送财政平台」**，校验通过的记录分批上送；
4. 平台退回的记录进入**错误清单**，可导出 CSV 发给村级协理员修正；
5. 修正后重新导入即可（失败记录不会拦截重复导入，已发放成功的会）。

## 演示数据说明

`sample_data/城关镇_补贴名单_演示.csv` 共 25 行，覆盖全部校验场景：

- 12 行完全正常 → 上送成功
- 4 行格式合法但被平台退回（触发模拟规则，见下）
- 9 行格式/重复校验失败（身份证校验位错、银行卡错、负金额、三位小数、
  非数字金额、文件内重复、乡镇不符、乡镇为空、姓名过短）

### 模拟财政平台退回规则（`fiscal_client.py`）

真实环境将 `MockFiscalPlatform` 替换为财政平台 HTTP 接口即可，契约不变。

| 规则 | 退回原因 |
| --- | --- |
| 银行卡号末 6 位含 `0000` | 账户已注销 |
| 单笔金额 > 50000 元 | 超过单笔发放限额 |
| 身份证号 `999` 开头 | 身份证信息与姓名不匹配 |
| 姓名含「异常」 | 收款人姓名与银行账户户名不符 |

## 数据库设计

- `users`：账号（乡镇字段为数据权限依据）
- `import_tasks`：导入任务（含各状态计数、所属乡镇）
- `subsidy_records`：名单明细（VALID/INVALID/SUCCESS/FAILED 状态机）
- `batches`：上送批次（每 50 笔一批，记录受理结果）

## 生产化建议

- 设置环境变量 `SECRET_KEY`；使用 HTTPS；密码定期轮换
- 增加 CSRF 防护（如 Flask-WTF）、登录失败锁定、操作审计日志
- 上送改为异步任务（Celery/RQ）+ 平台回执异步对账
- 数据库切换为 PostgreSQL/MySQL，身份证、银行卡号加密存储
